# 能力边界

TestAgent 是测试人员的"起草伙伴"，不是替代者。清楚哪些工作能交给它、哪些必须由人完成，能避免过度依赖与不当预期。

## 一张图看懂边界

```
┌──────────────────────────────────────────┐
│              测试方案完整流程              │
├──────────────────────────────────────────┤
│  需求澄清        ────► 测试人员         │
│  模板选择        ────► 测试人员         │
│  解析与生成      ◄────► TestAgent        │
│  自动审查与修复  ◄────► TestAgent        │
│  业务合理性判断  ────► 测试人员         │
│  风险评估        ────► 测试人员         │
│  测试数据准备    ────► 测试团队          │
│  最终方案评审    ────► 测试人员 + 团队  │
│  评审通过后执行  ────► 测试团队          │
└──────────────────────────────────────────┘
```

左边和右下的事项是测试人员/团队的职责；中间两个长方形是 TestAgent 的强项。

## TestAgent 能做什么

### ✅ 强项

- **解析多种资料格式**：Word、Markdown、PDF、图片、Excel。
- **识别模板结构**：章节、层级、表格、表头。
- **按模板填充内容**：每个章节按需求和模板要求生成。
- **自动审查**：检查结构完整性、内部一致性、明显缺漏。
- **自动修复**：在可修复范围内迭代一轮。
- **导出 Word**：按模板排版导出。
- **项目级上下文**：跨对话复用资料和知识库。
- **增量修改**：基于已生成产物做局部调整。

### ⚠️ 能做但需要人工复核

- **业务规则覆盖**：能列出规则，但完整性依赖需求资料是否清晰。
- **边界场景**：能识别常见边界（必填、唯一性、长度），但业务特定边界需要测试人员补充。
- **测试数据示例**：能给出占位示例，但真实可复现的测试数据需要测试团队准备。

### ❌ 不能做

- **替测试人员做业务判断**：例如"哪个模块是核心""哪个团队负责测试"。
- **运行测试**：TestAgent 只生成方案，不执行测试用例。
- **访问未授权的系统**：例如你的 Jira、TestRail、Confluence——除非通过知识库集成。
- **替代需求澄清**：需求不清楚时，AI 会做"合理假设"，但假设可能与你的真实意图不符。
- **保证零错误**：任何 AI 生成内容都必须经过人工复核。

## 哪些结论仍需人工确认？

### 1. 业务规则的覆盖度

AI 可以从需求中抽取规则，但：

- 需求文档中没写明的"潜规则"AI 看不到。
- 跨模块的关联规则 AI 不一定能拼起来。
- 业务方口头表达过的规则（未落文档）AI 不知道。

**人工复核点**：通读生成结果，对照需求文档，标出遗漏的规则。

### 2. 风险评估

AI 可以基于模板的"风险与依赖"章节生成风险列表，但：

- 风险等级排序需要结合团队经验。
- 缓解措施需要测试团队根据实际情况给出。
- 跨项目的历史风险依赖团队记忆。

**人工复核点**：对每条风险问一句"这个等级和缓解措施靠谱吗"。

### 3. 测试数据

AI 给出的测试数据是占位示例，例如"手机号 13800138000"。真实测试需要：

- 符合业务规则的合法数据。
- 边界值（最大、最小、刚好等于阈值）。
- 异常值（非法格式、超长、特殊字符）。

**人工复核点**：把占位数据替换成业务可用的真实数据，并补充边界场景。

### 4. 环境与依赖

AI 列出"测试环境"和"外部依赖"，但：

- 真实环境配置（服务器地址、账号、网络）依赖运维。
- 第三方系统的 mock 方式需要团队决定。
- 数据准备的时间窗口依赖业务节奏。

**人工复核点**：环境清单与运维团队确认。

### 5. 与历史方案的一致性

如果公司有历史测试方案，新方案需要与之保持术语、风格、引用方式一致。AI 不一定能完全对齐。

**人工复核点**：术语统一、引用规范、与其他方案的关联。

## 不当预期的常见表现

### "它应该能直接跑测试"

不能。TestAgent 只生成方案，不执行测试。执行测试需要测试团队按方案手动或通过自动化工具完成。

### "它应该能看截图直接懂业务"

部分能。TestAgent 支持 OCR 和视觉理解，但：

- 截图内容只是辅助信息，不是主要输入。
- 文字版需求仍然必需。
- 复杂流程图建议转为文字描述。

### "它应该能保证零错误"

不能。任何 AI 生成内容都有出错可能，包括：

- 字段名拼写错误。
- 业务规则理解偏差。
- 章节归属错位。
- 重复或遗漏。

TestAgent 的自动审查能捕获大部分模式错误，但业务错误仍需人工把关。

### "它应该能 100% 替代测试人员"

不能。TestAgent 处理的是起草、整理、审查、排版等机械工作。业务判断、风险评估、跨团队协作、责任主体等仍是测试人员的核心职责。

## 如何合理使用

| 该交给 TestAgent | 该留在测试人员手上 |
| --- | --- |
| 解析资料、抽取结构 | 业务澄清、术语解释 |
| 按模板生成章节 | 模板选择与定制 |
| 内部一致性检查 | 业务规则完备性判断 |
| 自动修复常见格式问题 | 风险评估与优先级 |
| 导出 Word | 测试数据准备 |
| 跨对话复用上下文 | 跨团队评审 |
| 增量修改章节 | 最终方案评审与签字 |

## 责任主体原则

TestAgent 提供的所有内容只是"建议"，最终方案以**测试人员的修改版**为准。如果自动审查结论与你的判断不一致，请以你的判断为准；如果自动审查未发现但你发现了问题，请直接修改。
