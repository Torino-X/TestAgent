# 核心能力

TestAgent 的能力围绕"理解输入 → 按模板生成 → 检查结果 → 持续协作"展开。理解这些能力的边界，能让你更准确地选择何时使用、何时人工介入。

## 资料理解

TestAgent 能从多种格式的资料中提取测试相关信息：

- **Word / Markdown / PDF / TXT**：解析为文本后抽取字段、流程、规则、角色。
- **图片（原型图、流程图）**：支持 OCR 或视觉理解（需在【系统设置 → 图像能力】中配置）。
- **资料库 / 项目资料**：跨对话复用，避免重复上传。
- **知识库**：对接企业知识库后，可在生成时检索业务制度、历史项目等参考信息。

**优势**：把不同来源的资料拼成统一上下文，无需手动整理。

**限制**：解析依赖文件可读性——扫描件 PDF（图片型）必须依赖 OCR 能力；加密文档无法解析。

## 模板驱动生成

模板决定输出结构，资料决定输出内容：

- **章节识别**：自动识别模板的一级、二级标题，按层级切分章节。
- **章节确认**：在生成前弹出确认卡片，让你选择每章由 AI 生成或保留原样。
- **风格保持**：尽可能沿用模板的标题样式、表格结构与排版特征。
- **多格式支持**：Word（.docx）、Excel（.xlsx）。

**优势**：团队规范与生成内容解耦。模板升级后，所有后续生成结果自动符合新规范。

**限制**：复杂排版（嵌套表格、合并单元格、自定义样式）可能在导出时出现格式丢失，需要在"格式丢失确认"步骤处理。

## 自动审查与修复

每一份生成结果都附带自动审查：

- **结构完整性**：检查必填章节是否齐全、有无遗漏。
- **内部一致性**：检查不同章节是否存在冲突（例如测试范围与功能测试分析对不上）。
- **明显缺漏**：标记可能缺失的关键场景（例如没有覆盖异常路径）。
- **自动修复**：在可修复的范围内尝试一轮修复，常见问题会被处理。

**优势**：把"我自己读一遍才发现漏了哪一节"的工作前置完成。

**限制**：自动审查只覆盖模式级风险，业务合理性仍需人工判断。

## 项目化协作

项目（Project）是 TestAgent 中组织多次相关测试工作的容器：

- **对话**：项目内的多个聊天共享资料上下文。
- **资料**：项目级上传/挂接的资料会被所有对话自动引用。
- **知识库连接**：项目级绑定知识库，避免每次聊天重复设置。
- **项目指令**：在项目设置中写一份"项目指令"，所有对话中的生成都会参考。
- **产物**：所有在该项目中生成的测试方案、审查报告都会自动归档到项目资产页。

**优势**：把"这次需求涉及多个对话"的工作流串起来，避免每次都要重复搭环境。

**限制**：项目适合"同一测试主题的多次对话"。完全无关的工作请开新项目，不要混在一起。

## 增量修改

生成完测试方案后，可以继续通过对话提修改要求：

- **章节级修改**：例如"在功能测试分析中补充权限校验场景"。
- **跨章节修改**：例如"统一所有章节里的术语"。
- **替换整段**：例如"把测试策略从风险驱动改成基于场景驱动"。

修改会作为**增量任务**继续处理，**不重新跑整个生成流程**——保留已有产物，只改差异部分。

**优势**：迭代速度快，避免每次都从头生成。

**限制**：增量修改基于已生成的产物结构。如果模板结构本身需要调整，建议重新生成。

## 流式协作体验

整个生成过程是流式的、可观察的：

- **实时进度**：每个章节旁边显示"待生成 / 生成中 / 已生成 / 已修复"。
- **工具调用可见**：LLM 调用、知识库检索、模板解析等步骤会显示在界面上。
- **断线续传**：意外刷新或断网后，重新进入聊天会从上次位置继续，不丢失已完成的工作。

## 能力地图

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| 资料理解 | 文档/图片/资料库 | 中间结构（范围、规则、字段、流程） |
| 模板驱动生成 | 模板 + 资料 + 章节确认 | 按章节填充的测试方案 |
| 自动审查与修复 | 生成结果 | 审查意见 + 修复后的产物 |
| 项目化协作 | 项目级资料/知识库/指令 | 跨对话复用的上下文 |
| 增量修改 | 自然语言修改要求 | 调整后的章节 |
| 流式协作 | 实时事件流 | 可视化进度与反馈 |
