# 什么是知识库

知识库（Knowledge Base）是 TestAgent 接入企业知识检索能力的入口。本节介绍知识库的概念、作用、与资料库的区别，以及何时需要启用。

## 一句话理解

**知识库 = AI 的"团队记忆"。**

让 AI 在生成测试方案时参考企业内部的业务制度、规范、历史项目，而不只是依赖通用知识。

## 知识库 vs 资料库

很多用户分不清"知识库"和"资料库"。它们都是 TestAgent 中组织文件的机制，但定位不同：

| 维度 | 资料库 | 知识库 |
| --- | --- | --- |
| 形态 | 个人文件柜 | 企业知识检索系统 |
| 内容 | 单个文件 | 文档库 + 分片 + 检索 |
| 检索 | 文件名 + 全文搜索 | 向量检索 + 关键词检索 |
| 适合 | 完整文档 | 长文档的片段 |
| 集成 | TestAgent 内置 | 外部知识库系统 |

简单地说：

- **资料库**存完整文件，适合"读全文"。
- **知识库**存可检索的文档片段，适合"找相关内容"。

例如：

- "公司财务报销制度"是一份完整的 PDF，存资料库或项目资料即可。
- "公司过去 50 个项目的测试方案合集"是大量文档的集合，存知识库便于检索片段。

## TestAgent 的知识库特性

### 1. 多知识库并行

- 一个 TestAgent 账户可以对接多个企业知识库。
- 一次生成可以同时检索多个知识库。
- 每个知识库可设置启用/禁用。

### 2. 分片与标签

- 知识库的文档被切分为多个分片（chunk）。
- 每个分片可打多个标签（label）。
- 检索时可以按标签过滤。

### 3. 多种分片方法

- general（通用分片）：按段落、章节切分。
- parent_child（父子分片）：保留上下文层级。
- qa（问答分片）：按问答对切分。

### 4. 图片识别（可选）

- 文档中的图片可启用 OCR 或视觉识别。
- 让分片包含图片描述，便于检索。

### 5. 图谱关联

- 分片之间可建立关联。
- 检索时返回关联分片，提高召回率。

## 知识库的作用

### 在测试方案生成中的作用

当 AI 生成测试方案时，会从知识库检索：

- **业务制度**：例如"采购审批制度"。
- **团队规范**：例如"性能测试规范"。
- **历史项目**：例如"过去 50 个相似项目的测试方案"。
- **常见术语**：例如术语表。
- **常见风险**：例如"金融行业历史风险库"。

检索结果作为生成上下文的一部分，让 AI 写出更贴近团队实际的方案。

### 在问答中的作用

知识库问答（在生成测试方案之外的场景）：

- 用户问"公司财务报销制度是什么？"
- 系统检索知识库返回相关片段。
- AI 综合片段给出回答。

## 知识库的接入方式

### 1. 企业知识库（标准方式）

TestAgent 通过统一接口对接企业知识库：

- 配置知识库服务地址、API Key。
- 在 TestAgent 中"导入"企业知识库。
- 选择要启用的知识库。

这种方式适合：

- 公司已有知识库系统。
- 需要统一的权限与审计。

### 2. 文档上传方式

TestAgent 也支持把文档直接导入到对接的知识库：

- 在 TestAgent 知识库页面上传文档。
- 系统自动调用知识库接口完成导入。
- 等待分片与索引完成。

## 知识库的角色

### 系统级 vs 项目级

- **系统级知识库**：在【系统设置 → 知识库】中配置，作用于所有对话。
- **项目级知识库**：在【项目设置 → 知识库连接】中配置，仅作用于项目内对话。

项目级知识库优先于系统级。

### 知识库连接 vs 项目资料

- **项目资料**：上传或关联的完整文件，自动引用。
- **项目知识库**：绑定的知识库，按需检索。

详见 [项目资料 vs 项目知识库](#项目资料-vs-项目知识库)。

## 知识库的相关操作

### 检查配置

在【知识库】页面 →【设置】标签：

- 配置知识库服务地址。
- 配置 API Key。
- 测试连接。
- 查看连接状态。

### 创建知识库

在【知识库】页面 →【知识库】标签 →【新建知识库】：

- 填写知识库名称、描述。
- 选择分片方法、标签。
- 创建后获得知识库 ID。

### 导入文档

在【知识库】页面 →【文档】标签 →【上传文档】：

- 选择目标知识库。
- 上传文档文件。
- 等待分片与索引。

### 检索测试

在【知识库】页面 →【检索测试】标签：

- 输入查询关键词。
- 选择知识库与标签。
- 系统返回命中片段。
- 验证检索效果。

### 标签管理

在【知识库】页面 →【标签】标签：

- 创建标签。
- 给文档/分片打标签。
- 检索时按标签过滤。

### 分片管理

在【知识库】页面 →【分片】标签：

- 查看分片列表。
- 编辑分片内容。
- 关联相邻分片。
- 删除/禁用分片。

## 何时需要启用知识库？

### 适合启用

- ✅ **企业有内部规范**：制度、规范、流程类文档，希望 AI 引用。
- ✅ **历史项目丰富**：希望 AI 参考过去项目的测试方案。
- ✅ **行业知识专精**：金融、医疗、政企等行业有特定术语与要求。
- ✅ **团队规模大**：测试团队多人协作，需要统一的"知识源"。

### 不需要启用

- ❌ **小型团队或个人**：可能资料库 + 项目资料已足够。
- ❌ **一次性需求**：知识库接入成本高于收益。
- ❌ **知识库内容质量不高**：低质量知识库会让生成结果偏离。

## 知识库的内容来源

知识库的内容通常来自：

| 来源 | 说明 |
| --- | --- |
| 公司制度文档 | HR、财务、采购等制度 |
| 行业规范 | 国家标准、行业标准 |
| 历史项目档案 | 历史项目的测试方案、总结 |
| 团队规范 | 团队内部的测试规范、命名约定 |
| 业务术语表 | 业务术语、缩写解释 |
| 风险案例库 | 历史风险与缓解措施 |
| 工具使用手册 | JMeter、Selenium 等工具手册 |

## 知识库的使用成本

### 时间成本

- **接入**：配置服务地址、API Key（一次性，约 1 小时）。
- **导入文档**：上传 + 分片 + 索引（按文档量，文档多可能数小时）。
- **持续维护**：定期更新内容、调整标签。

### 额度成本

- **检索**：每次生成会消耗少量知识库检索额度。
- **生成**：知识库内容会增加上下文长度，可能让生成更慢或更贵。

### 维护成本

- 内容过期需要清理。
- 分片质量需要定期 review。
- 标签需要随业务调整。

## 与"上下文引擎"的关系

TestAgent 的"上下文引擎"（Context Engine）是另一个高级特性，它在知识库之上提供了更精细的上下文管理：

- **知识库**：检索相关的片段。
- **上下文引擎**：把片段按优先级、相关性、token 预算筛选。

普通用户主要使用知识库即可，高级用户可以探索上下文引擎。
