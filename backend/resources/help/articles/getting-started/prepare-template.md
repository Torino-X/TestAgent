# 准备测试方案模板

测试方案模板决定了 TestAgent 的最终交付物长什么样。模板决定结构，资料决定内容，两者缺一不可。

## 什么是测试方案模板

测试方案模板是带有明确"骨架结构"的文档，可以是：

- **Word 文档**（.docx）—— 最常见，内部包含标题样式或表格。
- **Excel 工作簿**（.xlsx）—— 适合测试用例模板。

模板的核心价值在于：

1. **让团队有统一的输出格式**，避免每次生成结果参差不齐。
2. **让 AI 有清晰的填充位置**，知道每节应该写什么。
3. **让审查者有可比对的基线**，便于快速识别偏离或缺漏。

## 模板的两个来源

### 来源一：模板市场（推荐）

模板市场是 TestAgent 内置的、由团队维护的高质量模板集合：

- 按行业（金融、政企、互联网等）和测试类型（功能、性能、安全等）分类。
- 每份模板都有真实样例和说明。
- 一键【保存】到"我的模板"即可在新聊天中使用。

适合没有自定义模板的团队，或希望先看看行业惯例再确定自有模板的情况。

### 来源二：自己上传

如果你的团队已有标准 Word 模板，可以直接上传：

1. 在模板市场顶部点击【上传模板】。
2. 填写模板名称、分类、描述和标签。
3. 上传文件后模板进入【我的模板】列表。
4. 选择"是否发布到模板市场"——勾选后团队其他成员也能看到。

适合有强公司规范、需要稳定复用模板的团队。

## 一份"好模板"的特征

TestAgent 依赖标题层级和章节名称识别结构。模板质量直接决定识别准确度。

### 1. 标题层级清晰稳定

- 使用 Word 的【标题样式】（标题 1 / 标题 2 / 标题 3）或直接维护标题字号。
- 不要只靠字号或加粗表达层级——一旦字号统一，结构就丢失了。
- 一级标题数量建议 5–12 个，对应测试方案的主要章节。

### 2. 章节名称语义明确

✅ 好的命名：测试范围、测试策略、功能测试分析、接口测试分析、测试环境、测试数据、风险与依赖。

❌ 不推荐的命名：第一节、其他、补充、待定、未命名。

### 3. 固定内容与待生成内容分离

- 封面、版本号、审批签字栏、术语表等固定信息建议保留为"非 AI 章节"。
- 测试范围、测试策略、具体功能分析等需要结合需求重写的内容标记为"AI 章节"。
- 这种划分让"章节确认"步骤更轻松，避免重要信息被误覆盖。

### 4. 表格简单可识别

- 每张表的表头写在第一行，表头单元格不要合并。
- 避免：跨页大表、嵌套表格、连续合并单元格、超长单元格。

### 5. 占位内容简洁

模板中可以保留简短填写提示（如"【此处描述测试范围】"），但应删除旧项目的真实数据、截图或样例文字。这些旧内容会被 LLM 当作"上下文"误用。

## 上传前的检查清单

- [ ] 标题样式正确，至少存在 2 个层级（一级 + 二级）。
- [ ] 一级标题数量 5–15 个，覆盖完整测试方案结构。
- [ ] 表格无嵌套、无大面积合并。
- [ ] 没有遗留的真实业务数据或截图。
- [ ] 文件大小合理（通常不超过 30 MB）。
- [ ] 文件可正常打开（.docx / .xlsx，未损坏）。

## 选模板时的取舍

| 场景 | 建议 |
| --- | --- |
| 第一次使用、没有团队规范 | 从模板市场选一份行业通用模板 |
| 团队已有标准 Word 模板 | 直接上传到"我的模板"，无需发布到市场 |
| 不同项目需要不同结构 | 在"我的模板"中保留多个模板，按项目选用 |
| 想推动团队使用统一模板 | 在模板市场选好模板并发布，所有成员一键保存 |
