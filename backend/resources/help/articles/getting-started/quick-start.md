# 5 分钟快速开始

TestAgent 围绕"需求资料 + 测试方案模板 → 结构化测试方案"这条主线工作。准备好两类输入后，在聊天中发起一次任务，就能得到一份按模板结构生成、可下载 Word 的测试方案。

## 一句话理解工作流

- **需求资料**告诉 TestAgent "要测什么"，例如需求文档、业务规则、原型说明、接口描述。
- **测试方案模板**告诉 TestAgent "按什么结构交付"，例如你团队标准的 Word 模板或从模板市场保存的模板。
- **TestAgent** 解析需求 → 解析模板 → 按章节生成 → 自动审查与修复 → 导出 Word。

整个过程会在聊天中以流式事件的方式呈现：你可以看到"正在分析需求""正在生成第 N 章"等进度；遇到需要确认的步骤（章节确认、格式丢失确认）时，页面会暂停等你处理。

## 开始前准备

1. **准备一份需求资料**。可以是 Word、Markdown、PDF 等任意文本格式。资料应当包含测试范围、业务规则、关键流程与验收标准。第一次体验建议选择范围较小、规则清晰的单一功能，便于快速核对结果。
2. **准备一个测试方案模板**。可以是从模板市场保存的现成模板，也可以是你上传的 Word / Excel 模板。模板决定了最终交付物的章节结构和排版。
3. **确认文件所有权**。请只上传你有使用权的文档。TestAgent 不会将你的文件用于训练或对外分享。

:::tip
测试方案生成会消耗 LLM 额度。如果你还没有配置 LLM，请先到【系统设置】填写模型服务地址、Key 和模型名。
:::

## 发起生成

1. 进入 TestAgent 任意一个新聊天，或在已有项目里点击"开始新聊天"。
2. 在输入框中明确表达生成意图，例如："请基于这份需求生成测试方案"。
3. 通过【附件】按钮或拖拽上传需求文档和模板文件——这两类文件会分别被识别为 `requirement_doc`（需求文档）和 `test_plan_template`（测试方案模板）。
4. 等待系统弹出章节确认卡片：每一章可以选"由 AI 生成"或"保留原样"。系统默认勾选需要重写的业务章节，封面、术语说明等固定信息建议保留。
5. 点击【确认并生成】，任务正式启动。

## 查看进度与结果

- 任务开始后，输入框上方会出现进度条和章节状态。可以打开"任务详情"看到每个章节是"生成中""已生成"还是"已修复"。
- 如果生成过程中某些章节被认为需要重新生成（例如审查发现重大遗漏），系统会自动尝试修复一轮。
- 如果导出时检测到格式丢失（例如模板中包含复杂表格或样式），系统会弹出"格式丢失确认"，你可以选择接受或重试一次。
- 完成后会显示"任务完成"卡片，列出所有章节摘要，并提供查看、下载 Word 的入口。

## 检查和交付

1. **先看自动审查结论**：生成结果会附带自动审查意见，标出可能的遗漏、冲突或风险点。
2. **再人工复核关键内容**：重点核对业务规则、边界条件、测试数据、风险评估，这些仍需要测试人员的专业判断。
3. **按需修改**：可以在对话中继续提修改要求，例如"在功能测试分析中补充接口鉴权场景"。系统会在当前产物上做增量调整，不会从头再来。
4. **下载 Word**：从产物卡片或项目资产页一键下载 Word 文档，用于评审、归档或交接。
