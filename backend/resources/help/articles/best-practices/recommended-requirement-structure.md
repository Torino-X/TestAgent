# 推荐需求文档结构

需求文档是 TestAgent 理解"测什么"的输入。本节给出推荐的需求文档结构，帮助你写出 AI 易于消化、生成质量稳定的文档。

## 为什么结构很重要？

普通 AI 工具对"自由文本"也能给出回答，但 TestAgent 把需求文档作为结构化输入。结构化的需求文档能：

- 让 AI 准确抽取范围、规则、字段、流程。
- 让自动审查能识别"需求 vs 生成"的偏差。
- 让生成结果可追溯、可复核。

## 一句话原则

**需求文档应当"结构化、可验证、版本清晰"。**

## 推荐结构

下面是一套通用的需求文档结构，覆盖大多数测试场景：

```text
# 需求标题（功能 / 迭代名称）

## 1. 背景与目标
## 2. 范围
### 2.1 包含
### 2.2 不包含
## 3. 角色与权限
## 4. 业务流程
### 4.1 主流程
### 4.2 分支与异常
## 5. 业务规则
## 6. 字段定义
## 7. 接口与数据
## 8. 验收标准
## 9. 风险与依赖
## 10. 术语与缩略词
## 11. 附录
```

## 每章的写作要点

### 1. 背景与目标

简述：

- 业务背景：当前痛点 / 业务诉求。
- 迭代目标：本次要实现的目标。
- 预期收益：业务价值。

```markdown
## 1. 背景与目标

### 1.1 背景
当前采购订单审批流程依赖线下签字，效率低且难以追溯。

### 1.2 目标
本次迭代实现采购订单的线上审批，支持移动端操作。

### 1.3 预期收益
- 审批周期从 3 天缩短到 4 小时。
- 审批过程可追溯、可审计。
```

### 2. 范围

明确**包含什么、不包含什么**。

```markdown
## 2. 范围

### 2.1 包含
- 采购订单的创建、提交、审批、撤销。
- 移动端 H5 页面。
- 审批历史与审计日志。

### 2.2 不包含
- 采购订单的财务结算（独立项目）。
- PC 端原生应用（暂不实现）。
- 历史 OA 流程的数据迁移。
```

### 3. 角色与权限

列出角色及其权限。

```markdown
## 3. 角色与权限

| 角色 | 可执行操作 | 数据范围 |
| --- | --- | --- |
| 采购员 | 创建订单、提交审批、查看本人订单 | 本人创建 |
| 部门经理 | 审批本部门订单、查看本部门订单 | 本部门 |
| 总监 | 审批大额订单、查看全部订单 | 全量 |
| 财务 | 查看订单状态、不能审批 | 全量（只读） |
```

### 4. 业务流程

#### 主流程

```markdown
### 4.1 主流程

1. 采购员创建订单，填写商品、数量、金额、供应商。
2. 采购员提交订单，进入待审批状态。
3. 系统根据订单金额自动分配审批人（< 3 万元 → 部门经理；≥ 3 万元 → 总监）。
4. 审批人收到通知，查看订单详情，决定通过或驳回。
5. 通过 → 订单进入"已审批"，通知采购员。
6. 驳回 → 订单回到"草稿"，通知采购员修改。
```

#### 分支与异常

```markdown
### 4.2 分支与异常

- **审批人离职**：系统自动转交到审批人的直属上级。
- **审批超时（48 小时未处理）**：自动升级到上一级。
- **重复提交**：相同采购员、相同供应商、相同金额的订单 1 小时内不能重复提交。
- **金额异常**：单笔 > 100 万元需要 CFO 审批。
```

### 5. 业务规则

把规则写成**可验证的判断**。

```markdown
## 5. 业务规则

### 5.1 审批规则
- 规则 1：单笔金额 < 30,000 元 → 部门经理审批。
- 规则 2：30,000 ≤ 金额 < 50,000 元 → 部门经理 + 总监审批。
- 规则 3：金额 ≥ 50,000 元 → 部门经理 + 总监 + CFO 审批。
- 规则 4：金额 ≥ 1,000,000 元 → 需 CFO 单独审批一轮。

### 5.2 时间规则
- 规则 5：审批超时 24 小时自动通知审批人。
- 规则 6：审批超时 48 小时自动升级到上一级。

### 5.3 校验规则
- 规则 7：订单金额必须 > 0。
- 规则 8：同一供应商 30 天内累计金额不得超过 500 万元。
- 规则 9：订单商品数量必须为正整数。
```

### 6. 字段定义

```markdown
## 6. 字段定义

### 6.1 订单主表

| 字段 | 类型 | 必填 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| order_id | string | 是 | 32 位 | 系统自动生成 |
| amount | decimal | 是 | > 0 | 订单金额，单位元 |
| supplier_id | string | 是 | - | 供应商 ID |
| items | array | 是 | 1-100 | 商品明细，至少 1 条 |
| status | enum | 是 | draft/pending/approved/rejected | 订单状态 |
| created_at | datetime | 是 | - | 创建时间 |
| created_by | string | 是 | - | 创建人 ID |

### 6.2 商品明细

| 字段 | 类型 | 必填 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| product_id | string | 是 | - | 商品 ID |
| quantity | int | 是 | 1-9999 | 数量 |
| unit_price | decimal | 是 | > 0 | 单价 |
```

### 7. 接口与数据

```markdown
## 7. 接口与数据

### 7.1 主要接口
- POST /api/orders：创建订单。
- PATCH /api/orders/{id}：修改订单。
- POST /api/orders/{id}/submit：提交审批。
- POST /api/orders/{id}/approve：审批通过。
- POST /api/orders/{id}/reject：审批驳回。

### 7.2 关键错误码
- 4001：金额非法。
- 4002：商品清单为空。
- 4101：审批权限不足。
- 4102：订单状态不允许此操作。
- 4201：供应商 30 天累计超限。
```

### 8. 验收标准

```markdown
## 8. 验收标准

### 8.1 功能验收
- 所有角色能按权限执行对应操作。
- 所有规则按 §5 的定义生效。
- 所有异常路径按 §4.2 的定义处理。

### 8.2 性能验收
- 创建订单接口 P95 ≤ 800ms。
- 审批接口 P95 ≤ 500ms。
- 列表查询接口 P95 ≤ 1s。

### 8.3 兼容性验收
- iOS 14+ Safari。
- Android 9+ Chrome。
- 企业微信内置浏览器。

### 8.4 安全验收
- 所有接口需要鉴权。
- 敏感字段（金额、供应商）在数据库加密存储。
- 操作日志不可篡改。
```

### 9. 风险与依赖

```markdown
## 9. 风险与依赖

### 9.1 外部依赖
- 供应商主数据系统对接。
- 财务系统对接（独立项目）。

### 9.2 已知风险
- 风险 1：审批升级机制依赖 CRM 系统通知可靠性。
- 风险 2：大额订单审批链较长，可能影响业务效率。
```

### 10. 术语与缩略词

```markdown
## 10. 术语与缩略词

| 术语 | 解释 |
| --- | --- |
| 采购员 | 内部员工账号，可创建订单 |
| 采购客户 | 外部供应商账号（不参与审批） |
| 订单状态 | 草稿 draft / 待审批 pending / 已批准 approved / 已驳回 rejected |
| CFO | 首席财务官 |
```

## 写作风格建议

### ✅ 推荐

- **简洁**：每段不超过 5 行。
- **明确**：用可验证的判断代替抽象描述。
- **结构化**：用表格、列表代替段落。
- **一致**：同类内容用相同的描述模式。

### ❌ 避免

- ❌ 大段无标题文字。
- ❌ 抽象描述（"应该稳定""性能好"）。
- ❌ 模糊措辞（"等等""相关""类似"）。
- ❌ 重复内容（同一规则在不同章节出现多次）。
- ❌ 旧版本残留（v1 的内容没清理）。

## 文档维护

### 版本号

- 文档应带版本号，例如 `PRD-v2.3-采购审批.md`。
- 每次修订递增版本号。
- 在文档开头写明版本历史。

### 命名规范

```
<文档类型>-<版本>-<功能名>.<扩展名>

例：
- PRD-v2.3-采购审批.md
- API-doc-v1.0-订单服务.docx
- Test-Data-v1-采购审批.xlsx
```

### 评审

- 需求文档应经过业务方确认。
- 在 TestAgent 中使用时，建议在文档开头加上"已评审"标识。

## 完整示例

下面是一个完整的需求文档示例（精简版）：

```markdown
# PRD-v2.3 采购订单审批

## 1. 背景与目标
实现采购订单的线上审批。

## 2. 范围
### 2.1 包含
- 采购订单的创建、提交、审批、撤销。
- 移动端 H5 页面。

### 2.2 不包含
- 财务结算。
- 历史数据迁移。

## 3. 角色与权限
| 角色 | 可执行操作 |
| --- | --- |
| 采购员 | 创建、提交、撤销 |
| 部门经理 | 审批本部门订单 |
| 总监 | 审批大额订单 |
| CFO | 审批超大额订单 |

## 4. 业务流程
### 4.1 主流程
1. 采购员创建订单。
2. 采购员提交订单，进入待审批。
3. 系统分配审批人。
4. 审批人审批。
5. 通过 → 已审批；驳回 → 草稿。

### 4.2 分支与异常
- 审批人离职 → 直属上级。
- 超时 48h → 升级。

## 5. 业务规则
- 单笔 < 3 万 → 部门经理。
- 3-5 万 → 部门经理 + 总监。
- ≥ 5 万 → 部门经理 + 总监 + CFO。
- ≥ 100 万 → CFO 单独审批。

## 6. 字段定义
（参见上文 6.1 订单主表）

## 7. 接口与数据
- POST /api/orders
- PATCH /api/orders/{id}
- POST /api/orders/{id}/approve

## 8. 验收标准
- P95 ≤ 800ms。
- iOS 14+ / Android 9+。

## 9. 风险与依赖
- 依赖供应商主数据。

## 10. 术语与缩略词
- 采购员 = 内部员工账号。
```
