# 推荐模板结构

一份适合 TestAgent 的模板应当满足"层次清晰、命名明确、覆盖完整、可识别"。本节给出推荐结构与说明。

## 推荐结构（一级章节）

下面是一套适用于大多数测试场景的模板一级章节结构，按 14 章组织：

| # | 章节 | 由 AI 生成？ | 说明 |
| --- | --- | --- | --- |
| 1 | 封面 | 保留原样 | 项目编号、版本、密级 |
| 2 | 文档说明 | 保留原样 | 版本历史、修订记录 |
| 3 | 术语与缩略词 | 保留原样 | 业务术语、缩写解释 |
| 4 | 测试范围 | 由 AI 生成 | 功能模块、端到端场景、排除项 |
| 5 | 测试策略 | 由 AI 生成 | 测试方法、覆盖策略、阶段划分 |
| 6 | 功能测试分析 | 由 AI 生成 | 按功能点拆解测试要点 |
| 7 | 接口测试分析 | 由 AI 生成 | 接口清单、字段校验、幂等性 |
| 8 | 性能测试要点 | 由 AI 生成 | TPS、响应时间、错误率指标 |
| 9 | 安全测试要点 | 由 AI 生成 | 权限、加密、敏感字段 |
| 10 | 兼容性测试要点 | 由 AI 生成 | 终端、浏览器、操作系统 |
| 11 | 测试数据设计 | 由 AI 生成 | 字段示例、边界值、异常值 |
| 12 | 风险与依赖 | 由 AI 生成 | 风险清单、缓解措施 |
| 13 | 测试进度与人员安排 | 由 AI 生成 | 阶段、起止时间、负责人 |
| 14 | 审批签字栏 | 保留原样 | 责任人签字区 |

## 章节的层级建议

### 一级章节

- 数量建议 8–14 个。
- 章节名应简短（不超过 10 个汉字）。
- 一级章节之间不存在重复含义。

### 二级章节

- 每个一级章节下可以有 2–6 个二级章节。
- 二级章节是"该章节内的分组"。

例如"功能测试分析"下可以分：

```
6. 功能测试分析
   6.1 用户管理
   6.2 订单管理
   6.3 支付流程
   6.4 通知与消息
```

### 三级章节

- 谨慎使用。
- 仅在确实需要进一步细分时使用（例如"6.1.1 注册流程"）。
- 三级章节越多，模板越复杂，识别难度越高。

## 每章的占位说明

模板中每个章节应有简短占位，告诉 AI 该写什么。下面是推荐占位：

### 1. 封面

```
项目编号：________
版本：________
密级：________
编制人：________
日期：________
```

### 4. 测试范围

```
【描述测试范围，包含：
- 涉及的功能模块与版本
- 覆盖的端到端场景
- 不在本次测试范围的模块（明确排除）】
```

### 5. 测试策略

```
【描述测试策略，包含：
- 总体测试方法（基于风险 / 基于场景 / 基于需求）
- 测试阶段划分（单元 / 集成 / 系统 / 验收）
- 各阶段的覆盖目标】
```

### 6. 功能测试分析

```
【按功能点拆解测试要点，每个功能点至少包含：
- 功能描述
- 输入条件
- 预期输出
- 测试点（正常路径 / 异常路径 / 边界条件）】
```

### 7. 接口测试分析

```
【描述接口测试范围，包含：
- 接口清单（协议、方法、路径、覆盖度）
- 参数校验（必填、类型、长度、取值范围）
- 幂等性测试
- 错误码覆盖】
```

### 8. 性能测试要点

```
【描述性能测试要点，包含：
- TPS（每秒事务数）
- 响应时间（P50/P95/P99）
- 错误率
- 并发用户数】
```

### 9. 安全测试要点

```
【描述安全测试要点，包含：
- 权限模型（角色 / 操作 / 数据范围）
- 加密要求（传输加密 / 存储加密 / 敏感字段）
- 常见威胁（注入 / XSS / CSRF / 越权）】
```

### 10. 兼容性测试要点

```
【描述兼容性测试要点，包含：
- 终端类型（PC / 移动 / Pad）
- 浏览器与版本
- 操作系统与版本
- 分辨率】
```

### 11. 测试数据设计

```
【描述测试数据，包含：
- 合法数据示例
- 边界值（最大、最小、阈值）
- 异常数据（非法格式、超长、特殊字符）
- 数据构造方法】
```

### 12. 风险与依赖

```
【描述风险与依赖，包含：
- 风险项与等级（高 / 中 / 低）
- 缓解措施
- 外部依赖
- 已知阻塞项】
```

### 13. 测试进度与人员安排

```
【描述测试进度，包含：
- 测试阶段（用例设计 / 用例评审 / 测试执行 / 缺陷修复 / 回归）
- 起止时间
- 各阶段负责人
- 关键里程碑】
```

## 模板设计检查清单

在发布模板前对照检查：

- [ ] 一级章节数量 8–14 个。
- [ ] 每个一级章节有简短占位说明。
- [ ] 一级章节命名清晰，无重复含义。
- [ ] 每个一级章节下不超过 6 个二级章节。
- [ ] 表格表头在第一行，无大面积合并。
- [ ] 没有遗留的真实业务数据。
- [ ] 标题样式正确（一级 / 二级 / 三级）。
- [ ] 在 2–3 个真实需求上测试过。

## 不同场景的变体

### 金融行业变体

在通用模板基础上增加：

- 合规测试要点（监管要求、反洗钱）。
- 数据一致性测试（事务、并发、回滚）。

### 互联网产品变体

- 弱网测试要点。
- 灰度发布验证。

### 政企行业变体

- 等保测试要点。
- 数据出境合规。

### 数据迁移专项

- 数据校验规则。
- 迁移完整性验证。
- 回退方案验证。

## 模板升级建议

模板应当随业务迭代升级：

- 每季度 review 一次。
- 收集使用中遇到的识别错误，作为改进输入。
- 关注行业新要求（如新法规），及时加入对应章节。
