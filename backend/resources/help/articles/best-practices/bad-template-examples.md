# 常见错误模板

模板质量决定生成质量。本节列出常见的错误模板写法，帮助你避开这些坑。

## 一句话理解

**模板错误 = AI 识别失败 + 生成质量下降 + 团队规范不一致。**

避开了下面这些坑，模板质量就有基本保证。

## 错误 1：标题样式错误

### 现象

模板只用"加粗"或"加大字号"区分章节，没有用 Word 的标题样式。

### 后果

- AI 难以识别章节结构。
- 生成时把整篇文档当作一段连续文字。
- 自动审查无法定位问题。

### 正确做法

- 用 Word 内置的标题样式：标题 1 / 标题 2 / 标题 3。
- 在 Word 中：开始 → 样式 → 选择"标题 1"。

### 修复方法

1. 在 Word 中打开模板。
2. 选中所有"标题"段落。
3. 在样式下拉中选择对应的标题样式。
4. 保存并重新上传。

## 错误 2：层级混乱

### 现象

- 一级标题直接跳到三级，跳过二级。
- 二级标题嵌套在一级标题之前。
- 章节顺序混乱。

### 后果

- AI 难以理解章节归属。
- 生成内容归属到错误的章节。
- 自动审查章节完整性时出现误报。

### 正确做法

- 一级 → 二级 → 三级，顺序递增。
- 一级章节是顶级分类，二级是子分类。
- 三级只在确实需要时使用。

### 修复方法

调整标题层级，确保顺序为 1 → 2 → 3，没有跳跃。

## 错误 3：章节命名模糊

### 现象

- 章节名是"其他""补充""待定""未命名"。
- 章节名是"第一节""第二章"。
- 章节名含义模糊（"测试相关说明"）。

### 后果

- AI 不知道该章节该写什么。
- 生成内容可能是空泛的模板文字。
- 团队成员也无法理解章节意图。

### 正确做法

- 用语义明确的命名：测试范围、测试策略、功能测试分析、风险与依赖。
- 同一类内容用一致的命名模式。
- 避免同义词并存（不要同时有"测试策略"和"测试方法论"）。

### 修复方法

逐个章节重命名为语义明确的名称。

## 错误 4：表格设计过于复杂

### 现象 1：嵌套表格

```
┌─────────────────────┐
│ 表 1                │
│ ┌───────┐ ┌───────┐ │
│ │ 表 1.1│ │ 表 1.2│ │
│ └───────┘ └───────┘ │
└─────────────────────┘
```

### 现象 2：连续合并单元格

```
┌──────┬──────────────┐
│ 标题 │   内容       │
├──────┼──────┬───────┤
│      │ 子1 │ 子2    │
└──────┴──────┴───────┘
```

### 现象 3：跨页大表

一张表占据 5 页以上。

### 后果

- AI 难以解析表格结构。
- 导出 Word 时表格样式丢失。
- 自动审查可能误判。

### 正确做法

- 每个表格表达一件事，拆分为多个小表。
- 表头不合并，写在第一行。
- 单元格内容简洁，不超长。
- 避免跨页大表。

## 错误 5：占位内容缺失

### 现象

章节下没有任何占位说明，AI 不知道该写什么。

### 后果

- 生成内容空泛或猜测。
- 不同需求生成的结果差异巨大。

### 正确做法

每个章节下放 3 行以内的占位说明，明确告诉 AI 该写什么。

### 示例

❌ 没有占位：

```markdown
## 测试范围
（直接是空白）
```

✅ 有占位：

```markdown
## 测试范围
【描述测试范围，包含：
- 涉及的功能模块与版本
- 覆盖的端到端场景
- 不在本次测试范围的模块（明确排除）】
```

## 错误 6：占位内容过长

### 现象

占位文字写了半页到一页。

### 后果

- AI 难以分辨"占位"和"内容"。
- 生成内容可能直接复制占位。
- 占用 token，挤占生成空间。

### 正确做法

占位文字简洁，3 行以内最佳。

## 错误 7：模板里残留旧数据

### 现象

模板里包含：

- 旧项目的真实业务数据。
- 历史截图。
- 已废弃的术语。

### 后果

- AI 把旧数据当作"模板原文"保留。
- 生成内容混淆新旧版本。
- 自动审查可能误以为旧数据是当前需求的一部分。

### 正确做法

- 上传前清理旧数据。
- 用占位说明代替具体内容。
- 如果是参考样本，单独保存不要混入模板。

## 错误 8：模板章节过多或过少

### 现象 1：章节过多

一级章节超过 20 个，每个章节只有 2–3 行内容。

### 现象 2：章节过少

一级章节只有 2–3 个，缺少完整结构。

### 后果

- 过多：生成压力大，章节识别困难，导出耗时长。
- 过少：生成内容空泛，缺少覆盖。

### 正确做法

- 推荐 8–14 个一级章节。
- 少于 5 个：缺少完整结构。
- 多于 20 个：考虑合并或拆分模板。

## 错误 9：固定信息和待生成信息混杂

### 现象

封面信息（项目编号、版本、密级）和需要 AI 起草的内容放在同一个章节里。

### 后果

- 章节确认时无法单独选择"保留封面"。
- AI 可能覆盖封面信息。

### 正确做法

- 固定信息（封面、版本、术语、签字栏）放在独立章节。
- 待生成内容（测试范围、策略、分析）放在另一组章节。
- 章节确认时分别选择。

## 错误 10：表格表头不在第一行

### 现象

```
| 说明：以下为风险表 |
| --- |
| 风险项 | 等级 | 缓解措施 |
| --- | --- | --- |
| 风险 1 | 高 | ... |
```

### 后果

- AI 难以识别表头。
- 导出 Word 时表格解析失败。

### 正确做法

表头写在第一行，不要有前置说明行。

```
| 风险项 | 等级 | 缓解措施 |
| --- | --- | --- |
| 风险 1 | 高 | ... |
```

## 错误 11：自定义样式过度

### 现象

- 大量自定义字体、字号、颜色。
- 自定义编号（一、1.1、(1)、①）。
- 嵌入字体、特殊字符。

### 后果

- 导出 Word 时样式丢失。
- 在不同客户端显示不一致。

### 正确做法

- 使用 Word 内置样式。
- 字号、颜色保持简洁。
- 不要依赖自定义编号。

## 错误 12：模板混合 Word 与 Excel 风格

### 现象

模板名义上是 Word，但里面嵌入了 Excel 表格或宏。

### 后果

- AI 难以解析。
- 导出时宏或脚本丢失。

### 正确做法

- Word 模板只用 Word 原生表格。
- Excel 模板用于数据类内容（用例清单、数据矩阵）。
- 不要混用宏、脚本、自定义控件。

## 错误 13：模板带加密或权限保护

### 现象

模板被设置为"只读"或带密码保护。

### 后果

- AI 无法解析。
- 上传可能失败。

### 正确做法

- 取消保护后再上传。
- 模板本身不需要加密（结构是公开的）。

## 错误 14：模板含敏感信息

### 现象

模板里包含：

- 客户真实数据。
- 内部账号、密码。
- 未公开的财务数据。
- 个人身份信息。

### 后果

- 数据泄露风险。
- 违反合规要求。

### 正确做法

- 上传前清理敏感信息。
- 用占位符代替真实数据。
- 必要时在团队外分享时再上传公开版本。

## 错误检查清单

发布模板前对照检查：

- [ ] 标题样式正确（一级 / 二级 / 三级）。
- [ ] 一级章节数量 8–14 个。
- [ ] 每个章节有简短占位说明。
- [ ] 章节命名语义明确，无重复含义。
- [ ] 表格表头在第一行。
- [ ] 无嵌套表格、无大面积合并。
- [ ] 没有遗留的真实业务数据。
- [ ] 没有嵌入宏、脚本、自定义控件。
- [ ] 没有敏感信息。
- [ ] 没有加密或权限保护。
- [ ] 在 2–3 个真实需求上测试过。
