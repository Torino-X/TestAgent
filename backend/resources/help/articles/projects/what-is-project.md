# 什么是项目

项目（Project）是 TestAgent 中组织多次相关测试工作的容器。它把同一主题的对话、资料、生成产物集中管理，适合需要持续推进同一测试主题的场景。

## 一句话理解

**项目 = 测试工作的"工作空间"。**

类似文件夹，但比文件夹更强：

- 对话：项目内可以创建多个对话，每个对话有独立的消息历史。
- 资料：项目级共享的资料会被所有对话自动引用。
- 知识库连接：项目级绑定知识库，所有对话自动复用。
- 项目指令：项目设置中写一份"项目指令"，所有对话中的生成都会参考。
- 产物：项目内所有生成的测试方案、审查报告集中归档。

## 项目 vs 普通聊天

| 维度 | 普通聊天 | 项目 |
| --- | --- | --- |
| 对话数量 | 一个对话一个主题 | 一个项目多个对话 |
| 资料共享 | 每次重新上传 | 项目内共享 |
| 知识库连接 | 每次设置 | 项目级设置一次 |
| 项目指令 | 无 | 团队级规范可写入 |
| 产物归档 | 在资料库"系统生成"中 | 项目资产页集中可见 |
| 适用场景 | 一次性工作、临时提问 | 持续性、多对话工作 |

## 何时需要建项目？

### 适合建项目

- ✅ **同一产品/系统下的多个需求**：例如"采购系统 2026 年 Q3 的所有迭代"。
- ✅ **持续推进的测试主题**：例如"XX 项目性能专项"包含多次性能评估。
- ✅ **跨团队协作**：测试、设计、产品共用同一组资料。
- ✅ **多角色协同**：不同测试人员负责同一项目的不同模块。

### 不需要建项目

- ❌ **完全无关的工作**：例如"测试方案生成"+"PPT 排版咨询"。
- ❌ **一次性提问**：例如"XPath 怎么写"。
- ❌ **临时探索**：例如"看看 AI 工具能不能用"。

## 项目的核心组成

### 1. 项目基本信息

- **项目名称**：简短、明确，便于识别。
- **项目描述**：一两句话说明项目目标、范围。
- **创建时间 / 更新时间**：自动维护。

### 2. 对话（聊天）

项目内可以创建多个对话，每个对话：

- 有独立的标题、消息历史。
- 自动引用项目资料与知识库连接。
- 生成的产物归入项目资产页。

### 3. 项目资料

项目级上传或挂接的资料：

- 需求文档、接口说明、设计稿、参考规范等。
- 支持上传新文件或从资料库关联已有文件。
- 所有项目内对话自动引用。

### 4. 知识库连接

项目级绑定的知识库：

- 关联一个或多个企业知识库。
- 项目内所有对话的生成都会检索这些知识库。
- 与"个人级"知识库设置不同。

### 5. 项目指令

项目设置中可维护一份"项目指令"（Project Instructions）：

- 团队规范、术语表、引用约定。
- 测试覆盖度要求、风险评估标准。
- 项目特定的注意事项。

项目指令会被注入到每次生成的上下文，AI 会参考这些指令调整输出。

### 6. 项目资产

项目内所有生成的产物：

- 测试方案（Word 文件）。
- 审查报告。
- 中间产物（章节预览、修改记录）。

所有产物在项目资产页集中可见，可预览、下载、重命名、删除。

## 项目的生命周期

### 1. 创建

- 从侧边栏【项目】→【新建项目】。
- 填写名称、描述。
- 可选：上传初始资料、绑定知识库、设置项目指令。

### 2. 使用

- 在项目内创建多个对话。
- 上传/挂接项目资料。
- 发起测试方案生成。
- 在对话中提修改要求。
- 下载产物。

### 3. 维护

- 补充新的项目资料。
- 更新知识库连接。
- 调整项目指令。
- 归档旧对话。

### 4. 结束

- 项目目标达成后，项目可以保留作为历史归档。
- 也可以删除（项目中的对话会变回独立对话；资料和已生成产物不会被删除）。

## 项目的工作流示例

下面是一个典型的项目工作流：

```
1. 创建"采购系统 2026Q3 性能专项"项目
2. 上传：采购系统 PRD、性能需求文档、JMeter 使用规范
3. 绑定知识库：内部性能测试规范库
4. 设置项目指令："所有性能测试方案必须包含 TPS、响应时间、错误率三项指标"
5. 创建对话"：采购订单审批性能测试"
6. 发起测试方案生成（引用项目资料与指令）
7. 修改章节、下载 Word
8. 创建对话"：采购报表性能测试"
9. 重复生成流程
10. 项目结束时归档，所有产物保留
```

## 项目与"工作空间"的区别

一些用户把项目理解为"工作空间"，这不完全准确：

- **项目**：有业务含义的组织容器（同一业务主题）。
- **工作空间**：纯技术概念（同一组配置、同一组资料）。

TestAgent 的"项目"更接近"业务空间"，每个项目应有明确的业务目标。

## 项目的"边界"判断

判断一个工作应不应该建独立项目，看三个问题：

1. **是否涉及同一业务目标？** 是 → 建项目；否 → 独立对话。
2. **是否需要共享资料？** 是 → 建项目；否 → 独立对话。
3. **是否需要持续迭代？** 是 → 建项目；否 → 独立对话。

例如：

- "采购订单审批"和"采购报表生成"是同一业务目标，建一个项目。
- "采购订单审批"和"HR 系统入职流程"不是同一业务目标，分开。
- "XX 项目功能测试"和"XX 项目性能专项"在同一项目下分多个对话。
