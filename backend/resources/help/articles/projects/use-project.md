# 使用项目开展测试工作

本节介绍如何在项目内开展测试工作，包括创建对话、上传资料、发起生成、管理产物的完整流程。

## 创建项目

### 入口

- **侧边栏 → 项目 → 新建项目**
- **首页 → 项目列表 → 新建项目**

### 创建步骤

1. **填写项目名称**：简短、明确，例如"采购系统 2026Q3 性能专项"。
2. **填写项目描述**：一两句话说明项目目标。
3. **（可选）选择记忆模式**：
   - inherit：继承账户级设置。
   - on：在项目内启用记忆。
   - off：不使用项目记忆。
4. **点击【创建】**。

项目创建后自动进入项目详情页。

## 项目详情页布局

### 顶部

- 项目名称与描述
- 操作按钮：
  - **分享**：生成分享链接（团队内可见）。
  - **设置**（三个点按钮）：编辑项目、删除项目。

### 中部：新建对话输入框

项目详情页的核心区域，是一个对话输入框：

- **附件按钮**：上传或选择本次对话的文件。
- **文本输入**：填写对话的初始描述。
- **发送按钮**：发起新对话。

### 下方：标签页

项目详情页通常有三个标签：

| 标签 | 内容 |
| --- | --- |
| 对话 | 项目内的所有对话列表 |
| 项目资料 | 项目级上传或挂接的资料 |
| 测试资产 | 项目内生成的所有产物 |

## 创建对话

在项目内创建对话有两种方式：

### 方式 1：在项目输入框中发起

1. 在项目输入框中写对话的初始描述，例如"对采购订单审批做一次性能评估"。
2. 上传本次对话特有的资料（可选）。
3. 点击发送。

系统会自动创建一个新对话，并把项目资料、知识库连接、项目指令一并带入。

### 方式 2：从项目对话列表中新建

1. 切换到【对话】标签。
2. 点击【新建对话】按钮。
3. 进入空对话页面，发起新对话。

## 在项目对话中工作

新对话的工作流程与普通对话类似，但有两个差异：

### 差异 1：自动引用项目资料

项目资料不需要在每次对话中重新上传。它们会自动作为生成上下文的一部分。

### 差异 2：自动应用项目指令

项目指令会被注入到生成 prompt 中，AI 会参考这些指令调整输出。

例如项目指令写：

> "所有性能测试方案必须包含 TPS、响应时间、错误率三项指标。"

那么生成的"性能测试要点"章节会自动包含这三项指标。

## 项目的资料管理

### 上传资料

有两种方式：

- **上传新文件**：项目输入框的附件按钮，上传 .docx/.pdf/.md 等。
- **从资料库关联**：项目资料标签 → 添加来源 → 从资料库选择已有文件。

### 资料分类

每份资料可标记一个角色（source_role），便于检索：

- **requirement**：需求文档。
- **design**：设计文档。
- **reference**：参考资料。
- **other**：其他。

### 资料管理

项目资料标签页可以：

- 查看所有项目资料。
- 重命名资料。
- 移除资料（不会删除原始文件，只解除关联）。
- 调整资料角色。

## 项目的知识库连接

### 设置入口

项目详情页 → 设置 → 知识库连接。

### 配置方式

- 选择一个或多个企业知识库。
- 项目内所有对话的生成都会检索这些知识库。
- 不同对话可以基于这些知识库内容生成不同方案。

### 与个人知识库的关系

- **个人知识库**：在【系统设置 → 知识库】中配置，作用于所有对话。
- **项目知识库**：项目级设置，仅作用于项目内对话。
- 项目知识库优先于个人知识库。

## 项目的指令

### 设置入口

项目详情页 → 设置 → 项目指令。

### 指令内容

项目指令是一段自由文本，AI 会在每次生成时参考。建议包含：

- **团队术语表**：例如"采购员 = 内部账号、采购客户 = 外部账号"。
- **覆盖度要求**：例如"所有功能测试方案必须包含正常、异常、边界三类场景"。
- **引用规范**：例如"引用其他方案时使用 XX-XX 编号"。
- **特殊要求**：例如"所有接口测试必须考虑幂等性"。

### 指令示例

```text
# 团队术语

- 采购员：内部员工账号，可创建采购订单。
- 采购客户：外部供应商账号，可响应询价。
- 订单状态：草稿 → 待审批 → 已批准 → 已发货 → 已完成。

# 覆盖度要求

所有测试方案必须包含：
- 正常路径（happy path）
- 异常路径（error path）
- 边界条件（boundary）
- 性能要求（performance）
- 安全要求（security）

# 引用规范

引用其他测试方案时使用 "方案-编号" 格式，例如 "方案-FIN-2025-003"。

# 特殊要求

所有接口测试方案必须：
- 列出接口清单（协议、方法、路径）
- 包含参数校验
- 包含幂等性测试点
- 包含错误码覆盖
```

## 项目内的产物管理

项目内生成的所有测试方案会自动归档到【测试资产】标签：

- **预览**：点击查看方案内容。
- **下载**：下载 .docx 文件。
- **重命名**：修改资产显示名。
- **删除**：移至"最近删除"。

详见 [项目产物](/help/article/project-artifacts)。

## 项目的协作

### 团队成员共享

如果你的账户在团队下，项目通常是团队可见的：

- 团队成员可以在项目内查看资料、对话、产物。
- 部分操作（编辑、删除）需要权限。

### 分享

项目设置中可生成"分享链接"，把项目分享给团队外成员（只读）。

## 项目的删除

### 何时删除

- 项目目标已结束，不再需要。
- 误建的空项目。
- 测试用途的项目。

### 删除的影响

- 项目本身被删除。
- **项目中的对话**：变回独立对话，不再关联项目。
- **项目资料**：从项目中解除关联，但不会删除原始文件。
- **项目产物**：保留在资料库的"系统生成"分类下。
- **项目指令、知识库连接**：随项目删除。

### 删除前建议

- 下载关键产物作为本地归档。
- 确认没有对话还在依赖项目资料。
