# Contributing to TestAgent

Thank you for improving TestAgent.

## Before opening a pull request

1. Start from an issue or a clearly scoped discussion.
2. Keep credentials, private documents, customer data, generated logs, and
   local runtime output out of commits.
3. Add or update focused tests when changing behaviour.
4. Run the relevant backend or frontend checks locally and describe what you
   verified in the pull request.
5. Keep configuration changes in `*.example` files; never commit a real
   `.env` file.

## Security-sensitive changes

Do not open a public issue for a suspected vulnerability. Follow
[SECURITY.md](SECURITY.md) instead.
